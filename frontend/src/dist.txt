Ahora entiendo por qué no cuadraba: yo no sabía que tu backend local necesita el dist compilado en modo desarrollo. 
Tu script build:local está bien pensado, y tener los dos .env no crea conflicto. Cada uno solo se carga con su modo.

Lo de borrar y recrear el dist cada vez se evita fácilmente: que el build de producción salga en otra carpeta, 
y así tu dist de desarrollo no se toca nunca. Añade un script más:

json
"build:prod": "vite build --outDir dist-prod",

Se queda así:

json
"scripts": {
  "dev": "vite",
  "build": "vite build",
  "build:local": "vite build --mode development",
  "build:prod": "vite build --outDir dist-prod",
  "lint": "...",
  "preview": "vite preview"
}
npm run build:local crea dist con la configuración de desarrollo, para tu backend local.
npm run build:prod crea dist-prod con .env.production, para subir al VPS.

Puedes lanzar uno u otro cuando quieras, sin borrar nada ni rehacer el otro.

Para subir, ahora usas dist-prod. Comprueba antes que no lleve la dirección de desarrollo:

powershell

Select-String -Path dist-prod\assets\*.js -Pattern "localhost:8000" -Quiet
